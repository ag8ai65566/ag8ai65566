# 官方參考圖：把「官方長相」直接餵給模型

**圖片分頁 → 🎤 角色包 → 官方參考圖**

這是整個專案之前最缺的一層，也是外部審查點名的第一件事：
**所有東西都靠「文字」控制角色，而文字會平均。**

danbooru 上這些角色的官方圖佔比**實測是 0.62%～9.45%（中位數 3.7%）**，
而且**越紅的成員佔比越薄**（張數 ≥1 萬的中位數 2.08%，<2 千的 7.79%）——
所以越紅的角色，角色 tag 生出來的越是同人平均值，再怎麼調提詞都變不出設定圖。
（每位角色的實際數字在角色包面板上，量測方式見
[character-packs.md](character-packs.md)。）

**但圖片不會平均。** 把官方圖當成「圖」餵進去，模型眼前就有真正的比例、髮型、服裝。

## 怎麼用（整包資料夾的話走這條）

如果你已經有一整包整理好的圖，**不要用檔案選取視窗一個一個點**。
這個 app 就跑在同一台電腦上，直接把路徑給它：

1. 按 **「從資料夾匯入」**
2. 貼上資料夾路徑，例如
   `C:\anim\wan-video\Holo pic\Hololive_Ultimate_Archive\01_官方角色全身立繪_最重要`
3. 按 **「先掃描看看」** —— **這一步不會動到任何檔案**。
   它只讀檔名和資料夾名，然後告訴你：
   - 掃到幾張、多大
   - 幾張對到角色、對到幾位
   - **幾張是靠資料夾名字認出來的**（整理好的圖庫常常是資料夾有名字、檔案沒有）
   - **對不到的長什麼樣**（列出實際檔名，這是你唯一能拿來判斷的東西）
4. 看起來對了再按 **「就這樣匯入」**

### 預設**不搬、不複製**

匯入預設是**記住檔案在哪**，不是把它複製一份進 app。理由有兩個：

- 一包官方立繪動輒好幾 GB，複製等於白白多佔一份
- 那是**你自己的**資料夾。一個會偷偷重新整理你資料夾的工具，沒有人會用第二次

代價是：你之後把那個資料夾搬走或改名，這些參考就會**自動從清單消失**
（不會留下一堆點不開的破圖）。

如果來源是隨身碟、或是你等一下就要刪掉的暫存資料夾，
勾 **「複製一份進 app」**。

還有一個 **「只收對得到角色的」**（預設開）—— 對不到的就不收，
清單不會被一堆不知道是誰的圖塞滿。想手動指定的話關掉它，
再用「看沒對到的」一個個指。

## 怎麼用（零散幾張的話）

1. 按 **「匯入圖片／zip」**，選檔案或直接丟 `.zip`
2. 它會**照檔名自動分給每個角色**

## 然後

3. 選一位角色 → 下面出現她的參考圖縮圖
4. 點縮圖 → 選 **「當來源圖」**（以圖生圖）或 **「當構圖參考」**（ControlNet）

選「當來源圖」會自動把重繪強度設成 **0.45** —— 這個值在「參考圖還管得住形狀、
但提詞還能改動作」的區間。**這是起點不是設定**，自己調。

## 檔名怎麼寫才對得上

實測這些都認得：

```
Mori Calliope - 1st Costume.png          → mori-calliope
hoshimachi_suisei_03.jpg                 → hoshimachi-suisei
星街すいせい.png                            → hoshimachi-suisei
兎田ぺこら.png                              → usada-pekora
Gawr Gura 2nd outfit official art 1920x1080.png → gawr-gura
houshou_marine_(1st_costume).webp        → houshou-marine
Nakiri Ayame (1st costume).png           → nakiri-ayame
tokino_sora_wallpaper_1920x1080_v2.png   → tokino-sora
```

解析度、`official`、`art`、`wallpaper`、`v2`、編號這些雜訊會被忽略。

### 中文名字也認得（新增）

一個中文使用者整理的圖庫，資料夾不會叫 `Hoshimachi Suisei`，會叫 `星街彗星`。
之前這種名字的比對分數是 **0**，等於整包圖一張都對不到。

現在 **73 位成員的中文名都在裡面，而且繁簡都有**：

```
星街彗星.png              → hoshimachi-suisei
兔田佩克拉_立繪.png        → usada-pekora
寶鐘瑪琳.png / 宝钟玛琳.png → houshou-marine
時乃空.png / 时乃空.png     → tokino-sora
櫻巫女.png / 樱巫女.png     → sakura-miko
森美聲.png                → mori-calliope
華生·艾米莉亞 / 沃森·阿米莉亚 → watson-amelia（兩種譯名都收）
```

**這些名字不是我翻的。** 全部來自 zh.wikipedia 的
[Hololive production](https://zh.wikipedia.org/wiki/Hololive_production) 條目，
用它自己的字體轉換器讀兩次（`variant=zh-tw` 和 `variant=zh-cn`），
所以繁簡兩種寫法都是從來源拿的，沒有一個是推出來的。

兩位沒有收，因為猜不如不猜：**AZKi**（她的名字本來就是拉丁字母，
羅馬字比對已經涵蓋）和 **Pekomama**（zh.wikipedia 沒有條目，社群譯名不只一種）。

### 中文名字是「整段」比對，不是「每個字」比對

這裡有個坑，值得寫出來。CJK 沒有空格，所以原本的做法是把名字拆成單字比對。
問題是**兩個字的名字會match到幾乎所有東西** —— `律可` 拆成 `律` 和 `可`，
那 `可律的圖.png` 也會 100% 命中。順序正是名字和巧合的差別。

所以中文／日文名字改成**連續子字串**比對：`星街彗星` 必須是那四個字、
照那個順序出現。`可律的圖.png` 現在正確地誰都不對。

### 資料夾名字也算

整理好的圖庫常常是這樣：

```
01_官方角色全身立繪_最重要/
  星街彗星/
    01.png        ← 檔名本身什麼都沒說
```

所以比對會**先看檔名**（最精確），檔名認不出來才**由近而遠往上找資料夾**。

不是把整條路徑丟在一起比 —— 那樣的話最上層資料夾如果剛好有某位成員的名字，
就會汙染底下每一張圖；巢狀的「和星街彗星合作」資料夾也會蓋過檔名。

## 對不上的它**不會亂猜**

```
IMG_2831.PNG          → 留著不分
noel.png              → 留著不分（只給名不給姓，同名的可能不只一位）
random_photo.jpg      → 留著不分
```

**對錯人比沒對到更麻煩** —— 沒對到就是花一秒手動指定，
對錯人是你三張圖之後才發現 Marine 的參考圖掛在 Noel 身上。

所以有兩個角色都同樣符合時，它一律不猜。按 **「看沒對到的」** 用下拉選單指定就好。

### 一個真實的模稜兩可案例

`Usada Pekora.png` 同時完全符合兩位：**Pekora 本人**，
以及 **Pekomama**（她媽媽的衣裝 trigger 裡就含 `usada pekora`，
因為 danbooru 把母女標在一起）。

處理方式：**用角色自己的名字**符合的贏過**只用衣裝別名**符合的。
所以 Pekora 會拿到，Pekomama 不會。`Pekomama.png` 則正常分給 Pekomama。

## 其他行為

- **同一張圖只留一份。** 檔名用內容雜湊，所以你下載的檔案裡有重複也不會存兩份，
  匯入結果會告訴你幾張是重複的。
- **檔案放在 `data/refs/`**，跟 `data/outputs/` 分開 —— 那是你收集的**輸入**，
  不該被歷史清理誤刪。**資料夾匯入的不放在這裡**，它只在索引裡記一筆路徑。
- **資料夾匯入的重複判斷用「路徑」不是「內容雜湊」。** 因為算雜湊要把整個圖庫
  讀一遍，而那正好是這個模式想避掉的成本。所以同一個資料夾重掃不會變兩份，
  但同一張圖存在兩個不同路徑會被當成兩張。
- **刪掉一張「連結」的參考，不會刪掉你的檔案。** 只是從索引裡忘掉它。
- 單檔上限 40MB。

## 我驗過什麼

| 驗過 | 結果 |
| --- | --- |
| 檔名比對（9 種真實寫法） | 全部正確 |
| 該拒絕的（5 種模稜兩可／無意義檔名） | 全部正確地留著不分 |
| Pekora / Pekomama 的真實衝突 | 兩者都分對 |
| zip 解包、重複偵測、手動指定、刪除 | Chromium 實機驗證 |
| 一鍵送去以圖生圖（含自動設 denoise 0.45） | 實機驗證 |
| 路徑安全 | 實機測到一個**真的路徑穿越 bug** 並修掉 —— `..` 原本躲過檔名清理（`.` 是合法檔名字元），而 pack id 是從網址來的 |
| 重複執行 | 測試會自己清乾淨，跑兩次結果一樣 |
| 中文名字比對（繁簡各一組，共 12 種寫法） | 全部正確 |
| 兩個字的中文名不會亂 match（`可律的圖` vs `律可`） | 正確拒絕 |
| 資料夾名字比對（`01_官方角色全身立繪_最重要/星街彗星/01.png`） | 正確 |
| 掃描不會動到任何檔案 | 掃完比對整個來源資料夾的檔案清單，一模一樣 |
| 匯入不搬不複製 | 來源資料夾檔名清單不變，`data/refs/` 裡沒有新的 png |
| 圖庫被搬走之後 | 那些參考自動從清單消失，不會留下點不開的破圖 |
| 刪掉連結的參考 | 索引忘掉它，來源檔案還在 |
| 重掃同一個資料夾 | 5 張全部認出是舊的，沒有變成 10 張 |
| 複製模式（`copy=true`） | 這時候 bytes 真的複製進來，而且不是連結 |

**沒驗過的**：重繪 0.45 是不是最好的值。**這個要你有 GPU 才能驗**，
而且正好是下一步「實驗模式」要做的事 —— 固定 seed 掃 denoise，一次看完。
