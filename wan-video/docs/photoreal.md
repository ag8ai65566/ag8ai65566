# 真人短劇：本機、開放權重、無審核

這份文件回答一個具體的問題：**「我要做寫實真人的 NSFW 短劇，可以用 Seedance 嗎？」**

答案是不行，而且理由不是「不好用」，是**它不存在於任何可以在本機跑的形式**。
下面先把這件事查清楚，再講真正做得到的那條路。

---

## 一、Seedance 沒有公開權重。一個都沒有

這不是印象，是查的。查證日期 **2026-09-06**：

| 查了什麼 | 結果 |
|---|---|
| HuggingFace 搜 `seedance` | 15 個 repo。**每一個都只有 README，`weights: NONE`** |
| ByteDance 官方組織（`ByteDance`、`ByteDance-Seed`、`bytedance-research`）共 148 個模型 | 有 SeedVR2、Hyper-SD、AnimateDiff-Lightning、HuMo、Phantom…… **沒有 Seedance** |
| ModelScope 搜 `seedance` | 3 個。一個是 `Seedance2.0批量助手.zip`（API 批次提交工具），一個是 `H3Seedance2.0` |

那個 `H3Seedance2.0` 最說明問題。它的 metadata 是：

```yaml
base_model: MiniMax/MiniMax-H3
tags: [LoRA]
trigger_words: [Seedance2.0]
```

**74 MB，掛在另一個開源模型上，觸發詞叫 `Seedance2.0` 的 LoRA。**
有人訓練它去*模仿* Seedance 的風格。它不是 Seedance。

ComfyUI 官方文件把 Seedance 節點寫成 **API nodes**，程式碼直接呼叫 BytePlus 的
endpoint。所謂「Seedance 本地部署」在網路上找得到的每一個，拆開都是 API wrapper。

所以「Seedance 本地 NSFW」在三個層面同時不成立：**沒有權重可下載**、
**API 有內容審核**、**真人肖像還要額外的實名／活體驗證**。

### 那些「用 Seedance 做短劇」的公司呢

有，而且是真的 —— 但他們用的是**雲端 API**，不是本機權重。公開可查的案例
（劇火 AI、小藍梯漫劇工廠、杭州九紫源的《孤城照·驚變》）描述的都是
SaaS 平台或 API 串接，沒有任何一家宣稱持有權重。其中一個案例公開的算力成本是
**每分鐘約人民幣 1,000 元**。

至於「黃果短劇」這個名字：搜尋結果混著多個互不相干、近期註冊的網站，
**沒有找到足以證明它是一個統一製作體系的權威資料**，所以這份文件不拿那些
行銷說法當產業證據。

## 二、做得到的那條路

你要的其實是這個組合：**寫實真人 · NSFW · 全本機 · 不受審查 · 角色一致**。
開源做得到，只是不叫 Seedance。

> **先講清楚一件事**：開放權重放在本機推理，沒有雲端平台逐次攔截你的提詞——
> 但這不等於授權允許任何用途。每個模型的授權要各自看，
> 而且**這個 app 從頭到尾沒有生成過任何一張圖或一段影片**，
> 下面所有數字要嘛是上游官方規格，要嘛是別人量的，都標了出處。

### 三層

```
關鍵幀（寫實底模 + 角色 LoRA）→ 影片（Wan 2.2 I2V）→ 後期（補幀、超分、調色、剪）
      ↑ 這一層決定像不像那個人        ↑ 這一層決定動得對不對
```

#### 影片層

| 模型 | 授權 | 24GB | 適合 |
|---|---|---|---|
| **Wan 2.2 I2V-A14B**（FP8/GGUF） | Apache 2.0 | 要 offload | **首選**。寫實度和成人 LoRA 生態最好 |
| Wan 2.2 TI2V-5B | Apache 2.0 | 官方明確支援單卡 24GB | 快，細節略遜 |
| Wan 2.2 S2V-14B | Apache 2.0 | 要 FP8/offload | 有台詞的鏡頭，口型同一個 pass 出 |
| Wan 2.2 Animate-14B | Apache 2.0 | 要量化 | 動作轉移 |
| HunyuanVideo 1.5 | Tencent Community（**不適用 EU/UK/南韓**） | 官方最低 14GB | 第二引擎 |
| LTX-2.5 | 自訂 Community License | 官方建議 32GB+ | 原生同步音訊 |

「Wan I2V 最好」是社群共識，**不是 benchmark 結果** —— 目前沒有針對寫實成人
影片的可信獨立評測。同一批討論裡也持續有人回報模糊、動作不準和 LoRA 相容問題。

#### 關鍵幀層（這一層是本專案這次新增的）

「模型」分頁新增四個寫實底模。檔名、位元組數、SHA256 都是查證當日從
CivitAI API 讀的：

| 條目 | 版本 id | 架構 | 用途 |
|---|---|---|---|
| **LUSTIFY! ZENITH v9** | 3045803 | SDXL 1.0 | 寫實成人 |
| **Big Lust v1.6** | 1081768 | SDXL 1.0 | 寫實成人，另一種臉和膚質走向 |
| **CyberRealistic Pony v18** | 2884631 | **Pony** | 寫實成人，構圖控制較好 |
| **epiCRealism XL Pure** | 2514955 | SDXL 1.0 | 通用寫實，穿著衣服的鏡頭 |

兩件事要注意：

1. **鎖的是版本 id，不是模型 id。** LUSTIFY 的模型頁已經走到 v10、換成 Krea 2
   架構 —— 鎖模型的話，這裡的取樣參數會在某天靜靜地變成在講別的東西。
2. **CyberRealistic Pony 是 Pony 微調**，出來雖然是寫實的，但 score 詞和
   CLIP skip -2 這兩個規矩要留著，而且它只吃 Pony 的 LoRA。app 裡分開了。

下載走 CivitAI，要在「設定」分頁填 API key。key 只會送到 civitai.com。

#### 提詞：不能用同一套詞

`1girl`、`cowboy shot` 是 danbooru 的詞。寫實底模的標註是英文句子，
**沒有這兩個詞的位置**，送過去比較接近雜訊而不是指令。短劇分頁現在會照
底模的 `tag_style` 自動切換：

```
動漫底模： 1girl, 1boy, s1vra_person, cowboy shot, motel room at night
寫實底模： one adult woman, one adult man, s1vra_person,
          medium shot, from the knees up, 35mm lens, motel room at night
```

「畫風」也另開了一條線：7 個攝影配方（窗光人像、汽車旅館夜戲、手持緊張感、
下班後辦公室、霓虹夜街、高調明亮、車內），決定的是鏡頭、光、場景、調色，
不是線條和上色。**每一個都帶「看得到毛孔」那組** —— 塑膠皮膚是最常見也最
致命的破綻。

## 三、角色一致性：這一層只能靠 LoRA

動漫底模的訓練標註裡有 danbooru 角色標籤，所以打「hoshimachi suisei」
真的會叫出那張臉。**寫實底模沒有那個詞彙空間** —— 觸發詞在它眼裡只是一個
沒見過的字，每顆鏡頭都會是不同的人。

所以短劇分頁現在會檢查：選了寫實底模、而角色只有觸發詞沒有 LoRA，
就直接告訴你去「訓練角色」分頁。

### 訓練角色分頁

**這個 app 不執行訓練。** 訓練要 GPU 和好幾個小時，包一個沒跑過的訓練器當
按鈕，等於把沒驗證的東西當功能賣。它做的是沒有 GPU 也能做、而且新手真正
會失敗的那一半：

1. **觸發詞** —— 邊打邊檢查。用真名是最典型的錯誤：底模對那個名字本來就有
   印象，LoRA 會一直在跟它打架。要用一個沒有意義的字，像 `s1vra_person`。
2. **要準備哪些圖** —— 臉 30% / 半身 30% / 全身 25% / 困難條件 15%。
   給你實際張數，不是百分比。**不要整組都是同一個景別** ——
   LoRA 只學得到你給它看的東西，沒有全身圖就沒有全身的身份。
3. **標註怎麼寫** —— 寫進去的東西會被當成「可變的」，沒寫的會被併進觸發詞。
   所以姿勢、服裝、景別、光線都要寫，**臉不要寫**，臉就是要學的東西。
4. **檢查資料夾** —— 真的去讀你電腦上那個資料夾，抓：張數不足、長邊不到
   1024、整組同一個比例、缺標註、標註全都一樣、觸發詞沒出現在每張標註裡。
5. **產生設定檔** —— kohya_ss TOML / ai-toolkit YAML / diffusion-pipe TOML /
   OneTrainer JSON，連同執行指令，複製就能跑。

### 該用哪個訓練器

| 要訓什麼 | 用什麼 | 24GB |
|---|---|---|
| SDXL 身份 LoRA | **kohya_ss** 或 OneTrainer | 夠，1024 batch 1 很穩 |
| FLUX 身份 LoRA | **ai-toolkit** | 官方就附 24GB 設定 |
| Wan 影片／動作 LoRA | **diffusion-pipe** | 緊繃，要 block swap |
| LTX LoRA | 官方 `ltx-trainer` | 官方低配也要約 32GB |

**身份交給關鍵幀的 SDXL LoRA，不要一開始就訓 Wan 14B 身份 LoRA。**
影片 LoRA 比圖片 LoRA 貴一個數量級，而 Wan I2V 的工作是把已經鎖好身份的圖
動起來 —— 身份在關鍵幀就決定完了。

### 起點參數（SDXL 寫實人物）

```
dim 32 / alpha 16 · lr 1e-4 · text encoder 1e-5 · AdamW8bit · cosine
1024 · bucket 開、不 upscale · batch 1 · gradient checkpointing · cache latents
20-40 張 → 1200-2400 步
```

這組跟公開的人物訓練個案吻合。**是起點，不是調好的最佳值**，本專案沒有跑過。
設定檔裡每個 epoch 都會存一次 —— 一個 LoRA 在第 4 個 epoch 剛好、第 6 個
就過擬合是常態，不存中間版本你就沒得挑。

### 虛構人物那條路（建議走這條）

1. 用寫實底模生一個長相固定的虛構人物（固定 seed，挑到滿意）
2. 用 IP-Adapter / inpaint 擴成 20-50 張不同景別
3. 加上唯一觸發詞標註
4. 訓 LoRA
5. **淘汰塑膠皮膚和明顯漂移的那幾張，重訓**

第 5 步不是可選的：已知的風險就是把生成圖的瑕疵、單一光線和塑膠皮膚
一起蒸餾進 LoRA。

> **界線**：這個專案的角色一律是**虛構或生成的人物**，或你自己。
> 把特定真實人物的臉放進 NSFW 內容是未經同意的深偽，不在這裡的範圍內，
> 上面這條 synthetic identity 路線正是為此存在 —— 而且它的一致性反而更好、
> 更可控。

## 四、一集大概長什麼樣（60-90 秒、20-30 鏡、24GB）

| 階段 | 用什麼 | 時間 | 瓶頸 |
|---|---|---|---|
| 拆鏡 | 人工 | 20-60 分 | 一顆鏡頭別塞太多動作 |
| 建虛構人物 | 寫實底模 | 1-3 小時 | 身份和服裝漂移 |
| 建 reference set | IP-Adapter / inpaint | 2-6 小時 | 側臉、全身、小臉 |
| 訓角色 LoRA | kohya_ss | 1-6 小時／角色 | 過擬合、塑膠皮膚 |
| 每鏡關鍵幀 | 角色 LoRA + 寫實底模 | 1-3 小時／集 | 多角色互相污染 |
| 動作鏡 | Wan 2.2 I2V | Lightning 數分鐘／鏡 | offload、失敗重抽 |
| 台詞鏡 | 先做音檔 → Wan S2V | 更慢 | 音訊長度、口型 |
| 後期 | 補幀、超分、調色 | 1-4 小時 | 一致調色 |
| 剪輯 | FFmpeg / 達芬奇 / 剪映 | 1-3 小時 | 音畫節奏 |

**真正的瓶頸不是「按一次要多久」，是可用率。** 一顆鏡頭平均抽五次，
20 顆就是 100 次推理。合理的做法是：

```
480×832 + Lightning 大量抽草稿 → 鎖定 seed 和構圖 → 重要鏡改高品質重算 → 統一後期
```

有公開的個案報告「每顆鏡頭先出 5 張關鍵幀，通常 2-3 張是垃圾、1-2 張可用」，
但**沒有足夠樣本可以說出業界平均抽卡率**。把每鏡 4-8 個 seed 當**製作預算**
來排，而不是當查證過的數字。

### 尺寸

Wan I2V 的**輸出比例跟著輸入圖走**，不會自己裁成你設定的交付比例。所以：

- 關鍵幀就要做成 9:16。app 的預設已經改成 **768×1360**
  （9:16、長寬都是 16 的倍數、1.04MP 剛好是 SDXL 原生面積）。
  舊的 832×1216 是 2:3，每一顆都得再裁掉約 18%。
- 抽卡 480×832，定稿 720×1280，長寬對齊 16 的倍數。
- **不要**把 832×1216 先放大再塞進 480P Wan —— 官方會照 max_area 重新縮放，
  預先升解析度不會保住細節。原圖留著給臉部修復和最後超分用。
