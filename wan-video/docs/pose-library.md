# 動作／姿勢提詞庫（法典）

你傳的那份法典已經整理進 app 了。**提詞庫**分頁最上面就是「動作／姿勢庫」。

```
285 個動作 · 26 位畫師 · 417 條 tag 串
分成 8 大類 / 35 個小節（依照原文自己的分類）
```

---

## 怎麼用（一鍵）

1. 開 **提詞庫** 分頁
2. 上面「前面接上（角色提詞）」填你要畫的角色 —— 例如 `mori calliope, hololive`
   （或者先去角色包一鍵產生，再貼過來）
3. 搜或用「人數／分類」篩，點你要的動作
4. 出現的提詞框按 **送到圖片提詞** 就直接跳到圖片分頁開始生成

按 **接在現有提詞後面** 可以疊在你已經寫好的提詞上，不會蓋掉。

---

## 最重要的一件事：原文的權重在 ComfyUI 是**完全無效**的

這是我在做的過程中發現的，而且它可能就是你之前覺得「品質很糟糕」的原因。

法典是給 **NovelAI** 寫的。ComfyUI 的權重解析器（`comfy/sd1_clip.py` 的
`parse_parentheses` + `token_weights`，總共 45 行）**只認得一種語法**：

```
(x)        權重 × 1.1
(x:1.3)    權重 = 1.3（從最後一個冒號切）
```

就這樣，沒有別的。所以原文那些寫法在 ComfyUI 裡：

| 原文寫法 | ComfyUI 實際看到的 |
| --- | --- |
| `{{{vacuum fellatio}}}` | 權重 **1.0**，而且那六個大括號當成文字餵給 CLIP |
| `[[[deepthroat]]]` | 一樣。`[]` 是 A1111 的語法，ComfyUI 不吃 |
| `1.35::breasts press::` | 一樣。NAI4.5 語法，這裡沒有意義 |
| `-2::pov::` | 一樣 —— 而且「把 POV 推開」這個意圖**整個消失**，這是最糟的 |
| `elaina (majo no tabitabi)` | 括號被當成加權！`majo no tabitabi` 被 ×1.1，`elaina` 掉成普通 token |

**整份法典直接貼進去，等於所有 tag 都是平權重 1.0 外加一堆括號雜訊。**

所以匯入時全部換算過了，換算率用的是法典自己第 8 條寫的（NAI 的 `{}` `[]`
是每層 1.05，不是 SD 的 1.1）：

```
{{{{{vacuum fellatio}}}}}   →  (vacuum fellatio:1.28)      1.05^5
[[[deepthroat]]]            →  (deepthroat:0.86)           1/1.05^3
1.35::a,b::                 →  (a:1.35), (b:1.35)
elaina (majo no tabitabi)   →  elaina \(majo no tabitabi\)  括號跳脫，不再被當加權
```

換算結果**每一條都拿 ComfyUI 自己的解析器跑過**：624 個欄位、2643 個加權
tag，全部確認 CLIP 真的收到預期的權重。

### 兩件沒辦法直接換算的

- **負權重**。`-2::pov::` 在 SD 的正面提詞裡沒有對應寫法，所以那個 tag 被
  **移到負面提詞**、權重取絕對值。這是最接近的等價做法，而且介面會告訴你它搬了什麼。
- **`aritst:` 這個錯字**。法典裡有好幾處把 `artist:` 拼成 `aritst:`（你上次給我的
  例子也是這樣寫的）。**拼錯的話畫師完全不會生效** —— 那整段會被讀成「aritst」
  這個字加一個名字。已經全部修正。

## 畫師 tag 被單獨拉出來了

你特別要求的就是這個，而它比看起來重要。

法典每條動作的 tag 串裡都夾著**當初測試那個人自己的畫師串**，像這樣：

```
artist:ciloranko, [artist:hiten], [[artist:wlop]], {artist:na_tarapisu153}, ...
```

那是**他的**畫風選擇，不是動作的一部分。留在裡面的話：

- 會直接蓋掉你在角色包裡選的畫師（Hololive 原畫師那個功能就白做了）
- 而且權重還不低

所以畫師被抽成獨立一組，**預設關閉**：

- 勾「一起帶入原本的畫師 tag」才會加進去
- 旁邊有權重滑桿（0.3～1.8），會把整組畫師一起縮放
- 勾起來時會自動附上法典第 6 條建議的負面（`chibi, chibi inset, doll, fumo (doll)`）
  —— 畫師串很容易帶出小人／娃娃，這四個是原作者用來壓掉它的

介面也會列出這條原本用了哪幾位畫師，所以就算你不帶入，也可以看一眼、
自己挑一個去別的地方用。整份法典一共 **26 位畫師**，用最多的是
`hiten` `ningen mame` `wlop` `ciloranko`（各 30 幾條）。

### 順便：測試角色也被拉出來了

同樣的問題還有一層。法典有 70 條 tag 串裡帶著測試者當時用的角色，例如
`elaina (majo no tabitabi)`（26 次）、`w (arknights)`（12 次）——
**其中三個是 Hololive 成員**（`houshou marine (1st costume)`、
`shirogane noel`、`minato aqua`）。

這個最好笑也最要命：你想畫 Mori Calliope，結果提詞裡有個權重 1.48 的
Houshou Marine。所以角色也抽成獨立一組、預設關閉，介面會顯示「原作者是用這些角色測的」。

## 幾個介面上的細節

- **版本**。有些動作有好幾條 tag 串（`着衣版` / `无衣版` / `按头版`…），
  按鈕上會標「含畫師」「含角色」，不用點進去猜差在哪。
- **留空的位置**。原作者有幾條刻意留空要你自己填 —— `场景`（場景）、
  `武器`、`下身服装`、`食物`、`内容`。這些**沒有被刪掉**，介面會標出來提醒你換掉，
  因為原文備註本來就寫「自己添加场景tag」。
- **看原文 tag**。每條都可以展開看未經換算的原文，換算過程是可以查的。

---

## 被排除的東西

**2 條動作、5 個版本**因為帶有未成年相關 tag（`shota` / `child` /
`aged down`）被排除，介面上會顯示這個數字。這是唯一被過濾掉的東西，其他
一律照原文收錄。

比較細的一點：`幼儿园制服`（幼稚園制服）這條**留著**，只把它的「人物幼化版」
拿掉 —— 成年角色穿制服是服裝條目，把角色變成幼體才是問題。

## 之後有新版法典

法典會改版（你這份是 2026.5.27）。新版拿到之後：

```
python scripts/build-posebook.py <新檔案.txt> \
    --id sese-codex --name "涩涩法典（動作／姿勢提詞庫）" \
    --out app/poses/sese-codex.json
```

它會印出抓到幾條、幾個分類、幾位畫師，**而且如果條目數比上一版少就拒絕寫入**
（要強制覆蓋才加 `--force`）。這個保護是刻意加的：這種格式最容易出的錯，
就是解析器改壞了、資料默默少一半而沒人發現。

`app/poses/` 裡放幾個 JSON 就有幾個庫，所以以後多幾份法典也不用改程式。
