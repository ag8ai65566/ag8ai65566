## 1. 它叫我填 CivitAI API key 到 `.env`，但沒說怎麼填

**已經改成直接在網頁上填了。**

「設定」分頁 → 最上面就是「CivitAI API key」的輸入框 → 貼上 → 按「存起來」。

- key 去哪拿：civitai.com → 右上角頭像 → **Account settings** → **API Keys** → **Add API key**
- **不用重啟。** 存下去的同一秒就生效，剛才因為沒 key 而失敗的下載可以直接再按一次
- 它會寫進 `.env`，所以下次開也還在
- 顯示的時候是遮起來的（`abcd••••••••5678`），按 👁 才看得到
- `.env` 裡原本的註解和其他設定**一個字都不會動**

同一個地方也可以改 `COMFY_ARGS`（顯存不夠時填 `--lowvram`）。那個要重開 ComfyUI 才生效，畫面上會寫。

## 2. 「ComfyUI 落後 20 個更新 —— 在 ComfyUI 資料夾按 git pull」，那個 git pull 在哪？

**已經改成一顆按鈕了。** 「設定」分頁 → 更新 → **「立刻更新 ComfyUI」**。

它就是幫你在 `ComfyUI\` 資料夾裡跑 `git pull --ff-only`。安全的部分：

- 你的**模型不會動**（`ComfyUI\models\` 在 ComfyUI 自己的 `.gitignore` 裡）
- 你的 **custom node 不會動**（同理）
- 你的 `output\`、`input\`、`user\` 都不會動
- 如果你手動改過 ComfyUI 的檔案，它會**直接放棄並告訴你**，不會蓋掉你的修改

更新完要**重開 ComfyUI** 才生效（關掉 ComfyUI 那個黑視窗，再跑一次 `start.bat`）。

## 3. 為什麼 `update.bat` 更新完，ComfyUI 還是落後？

因為 `update.bat` **刻意不碰 `ComfyUI\` 這個資料夾**。

腳本裡有一行寫死的白名單：

```powershell
$keep = @('ComfyUI', 'venv', 'data', 'models', '.env')
```

這五個東西**永遠不覆蓋**。理由很簡單：你幾十 GB 的模型全部住在 `ComfyUI\models\` 裡面，
成品在 `data\`，你的 key 在 `.env`。更新程式碼不應該有機會碰到它們。

所以以前是這樣：`update.bat` 更新 app 的程式碼，ComfyUI 本體要你自己管。
那個「落後 20 個更新」就是這麼來的 —— 不是更新失敗，是根本沒更新那一塊。

**現在 `update.bat` 兩邊都做了。** 它在複製完程式碼之後，會另外在 ComfyUI 資料夾裡
跑一次 `git pull --ff-only`（模型還是碰不到，因為 git 根本不追蹤它們），
ComfyUI 的 `requirements.txt` 有變的話也順便補裝。

所以現在的答案是：**對，按 `update.bat` 就好，兩邊都會更新。**
不用重新下載任何模型 —— 一個 byte 都不用。

> 我在這台機器上用真的 git repo 跑過這條路徑：落後的會 fast-forward、
> 資料夾裡的未追蹤檔案（模擬 `models/big.safetensors`）原封不動、
> 有本機修改時會拒絕更新並保住你的修改。這三件事都有測試釘住。
> 但**我沒有你的機器**，所以第一次跑完請看最後一行寫的是 `UPDATE OK` 還是別的。

## 5. 我上傳 5 格的頁面，為什麼還能選 3 格？

**這是個真的洞，已經堵起來了。**

以前套用完分鏡之後，版型下拉選單還是可以改。改成 3 格之後，
每一格的提詞和每一格的構圖參考圖還停留在 5 格的狀態 —— 那不是選項，是陷阱。

現在按下「套用這個分鏡」之後：

- 版型選單**直接鎖住**，上面出現「🔒 分鏡已鎖定：照著 page01.png 量出來的 5 格」

  因為那些裁圖是綁在原本那些長方形上的，換版型之後就對不上了

## 6. 可以一次上傳好幾頁（連貫的）嗎？

**可以了。** 選檔案的時候直接多選（Ctrl 或 Shift 點），最多 12 頁。

- 每一頁**各自量分鏡**，上面會出現「第 1 頁 / 第 2 頁 / …」可以切著看
- 按「**N 頁一起畫**」→ 每一頁各排一個工作，一頁一頁畫出來
- 共用提詞、LoRA、種子基準全部共用，所以角色和畫風在整串裡是一致的

為什麼是「一頁一個成品」而不是拼成一張：一頁就是這個產生器的單位
（一個工作 = 一張拼好的頁面）。硬拼成一張的話，SDXL 的解析度會被攤薄到每一格都糊。

## 7. 畫質要好，我需要自己再裝別的 LoRA 嗎？會不會跟角色 LoRA 打架？

### 會打架，而且是同一組權重上的加法

多支 LoRA 是**疊加在同一組權重上**的。兩支都開 0.8 就是 1.6 的改動量，
臉和手就是從這裡開始崩 —— 而看起來會像「這個模型很爛」，其實是兩支在互相拉扯。

**app 現在會直接算給你看**：LoRA 清單下面會顯示「N 支 LoRA，總強度 X.XX」，
超過 1.6 就轉成警告色並告訴你怎麼調。

### 共存的三條規則

1. **角色 LoRA 高、畫風 LoRA 低。** 角色 0.7～0.8，畫風 0.4～0.6。
   角色是你要的主體，畫風只是上一層漆。
2. **把畫風那支的 🔗 拆開，CLIP 強度調到 0.2～0.3。**
   這是這個 app 有、ComfyUI 預設 UI 要接線才有的東西：LoRA 對「畫面」和對
   「文字理解」的影響力可以分開調。畫風 LoRA 的 CLIP 端調低，它就不會搶走
   你提詞裡的角色描述 —— 這是角色跑掉的頭號原因。
3. **一次只加一支新的。** 加一支、生四張、再決定要不要加下一支。
   同時開三支然後猜是哪支害的，是最花時間的做法。

### 但先別急著裝 LoRA —— 這些是免費的

在裝任何東西之前，這幾個開關已經在「進階設定」裡，不用下載、對畫質的幫助通常更大：

| 開關 | 做什麼 | 代價 |
| --- | --- | --- |
| **高解析重繪** | 先畫小圖再放大重畫一次。**手和臉的改善最明顯** | 時間大約多一倍 |
| **PAG**（建議 3） | 專治構圖崩、手畫壞 | 時間大約多一倍 |
| **FreeU** | 細節更立體 | 幾乎不花時間 |
| **放大模型** | 生完直接放大，不重畫 | 幾秒，要下載一個 65MB 的 |

**Pony 底模不需要「品質 LoRA」**。它的品質控制就是那串 `score_9, score_8_up, score_7_up`
（app 自動加）。在 Pony 上再疊一支品質 LoRA，多半只是白白吃掉你的強度預算。

## 8. 想讓生成的圖貼近原畫師的畫風（以 Mori Calliope 為例）

先講一個必須知道的事實，不然後面都是白做工：

> **Pony Diffusion V6 XL 在訓練時把畫師名字全部拿掉了**（這寫在它官方的
> model card 上）。所以在 Pony 上打 `by yukisame` 是三個 token 的空氣，
> 完全沒有作用。
>
> **Illustrious 和 NoobAI 相反** —— 它們是拿 danbooru 訓練的，畫師標籤原封不動。
> 寫法各自不同：Illustrious 是 `by <畫師>`，NoobAI 是 `artist:<畫師>`（見第 12 題）。

而你現在用的 Hololive Collection **是 Pony 訓練的**。這就是矛盾所在。

### app 已經把 75 位成員的原畫師都查好了

我從 [虛擬 YouTuber wiki](https://virtualyoutuber.fandom.com/) 的
`character_designer` 欄位抓出每位成員的原畫師，再到 danbooru 對出畫師標籤 ——
**而且是用畫師本人登記的推特網址去對的，不是用名字猜的**。
（用名字猜會把 Tokino Sora 的畫師「Ordan」對成 `edward_jordan`，9 張圖，
完全不相干的人。錯的畫師標籤比沒有更糟。）

結果：**75 位裡有 72 位有可用的畫師標籤**，例如

| 成員 | 原畫師 | 在 NoobAI 上寫 | 在 Illustrious 上寫 |

| Gawr Gura | Amashiro Natsuki（491 張） | `artist:amashiro_natsuki` | `by amashiro_natsuki` |
| Shirakami Fubuki | Nagishiro Mito（807 張） | `artist:nagishiro_mito` | `by nagishiro_mito` |

（寫法為什麼不一樣，見第 12 題。介面會照你選的底模自動用對的那個，不用自己記。）

查不到的 3 位（Watson Amelia、Pavolia Reine、Sakamata Chloe）**留空白，不亂填**。

選好成員之後，角色包裡會出現「**盡量貼近原畫師的畫風**」的勾，

### 四條路，各有取捨

| 做法 | 角色準度 | 畫風準度 | 說明 |
| --- | --- | --- | --- |
| **Pony + Hololive LoRA**（現在的預設） | 高 | Pony 的通用動漫風 | 畫師標籤在這裡沒作用，那個勾會是灰的並告訴你為什麼 |
| **Illustrious + `by 原畫師`，不用 LoRA** | **也很高** | **高** | 見下 |
| **Illustrious + Illustrious 版的角色 LoRA + `by 原畫師`** | 最高 | 高 | 要另外找一支 Illustrious 訓練的 Hololive LoRA |
| **任何底模 + 官方設定圖丟進 ControlNet** | 高 | 中～高 | 比例和服裝細節直接跟著官方走，**哪個底模都有效** |

**第二條路比你想的可行。** 我查了 danbooru：這 75 位裡有 **71 位的角色標籤超過 1000 張圖**

換過去之後記得：**把 Pony 版的 Hololive LoRA 取消勾選**（它在 Illustrious 上不但沒用，

**第四條路是最穩的補強**，而且可以跟前三條疊著用：到「官方設定圖」抓一張立繪，

> 那些設定圖是 hololive 的官方美術。自己在本機做同人圖沒問題，

## 9. 「照現成的一頁重畫」畫出來完全沒關係

**這不是壞掉，是缺兩個模型 —— 而且是我沒講清楚。** 這個功能需要兩個下載才會有效果：

| 缺了誰 | 結果 |
| --- | --- |
| **看圖分析模型**（約 380MB） | 讀不出每一格在畫什麼 → **每一格的提詞是空的** |
| **ControlNet 模型**（約 2.5GB） | 不會複製鏡頭和構圖 → **只複製格子的形狀** |
| **兩個都缺** | 量出格子 → 每格提詞空的 → 每格都只照你的共用提詞畫 → **四格長得一樣，跟原稿沒關係** |

第三行就是你遇到的情況。以前這件事只寫在一行小字裡，然後照樣讓你按下去。

**現在改成：**

- 漫畫模式一打開就會出現黃色警告條，寫明缺哪個、缺了會怎樣，旁邊直接是「到模型分頁下載」
- 按「套用這個分鏡」之後，狀態列會**老實講這次到底做到了什麼**：
  - 兩個都有 → 「分鏡、每一格的內容和構圖都帶進來了」
  - 只缺 tagger → 「構圖會照著原稿，內容要自己寫」
  - 只缺 ControlNet → 「會是類似的場景，不是同一個鏡頭」
  - 兩個都缺 → 「**內容和構圖都沒有**，畫出來只會照你自己打的字」

我另外把整條路徑從頭到尾追過一次（量分鏡 → 存裁圖 → 送出 → 組工作流程），
**模型有裝的時候線路是對的**：4 個裁圖確實變成 4 個 `LoadImage` → `Canny` →
`ControlNetApplyAdvanced`，接到 4 個取樣器上。這條路徑現在有測試釘住。

## 10. 丟了分鏡之後，怎麼取消？我下一張只想用提詞

**以前沒辦法，這是個真的洞。** 而且更糟的是：分鏡的構圖鎖定會跟著你切到單張圖片模式，
然後下一張圖被擋下來說「開了構圖鎖定，就要選一張構圖參考圖」—— 看起來像 app 壞了。

現在有三層：

1. **「✕ 清除分鏡」**（漫畫模式工具列，套用之後才出現）——
   一鍵全部還原：版型選單裡的「從頁面讀到的分鏡」拿掉、回到現成版型、
   構圖參考圖清掉、ControlNet 關掉。清完就是乾淨的普通模式。
2. **「解除鎖定」**（鎖定條上）—— 只解開版型選單，保留其他東西。
3. **切回「單張圖片」** —— 會自動把那一頁的構圖鎖定關掉，並告訴你它做了這件事。

## 12. 怎麼加重畫師的權重？（`{{artist:xxx}}` 有用嗎）

**你說對了一半：`artist:xxx` 確實是對的寫法 —— 但 `{{ }}` 沒有用。**

### `{{ }}` 是 NovelAI 的語法，ComfyUI 不吃

我把 ComfyUI 0.33 自己的解析器（`comfy/sd1_clip.py` 的 `token_weights()`）
抓出來跑了一次，結果是：

| 你打的 | ComfyUI 實際讀到的 |
| --- | --- |
| `{{artist:amashiro_natsuki}}` | 標籤 = **`{{artist:amashiro_natsuki}}`**，權重 1.0 ← 大括號變成提詞的一部分 |
| `(artist:amashiro_natsuki)` | 標籤 = `artist:amashiro_natsuki`，權重 **1.1** |
| `((artist:amashiro_natsuki))` | 權重 **1.21**（每層 ×1.1） |
| `(artist:amashiro_natsuki:1.3)` | 標籤 = `artist:amashiro_natsuki`，權重 **1.3** ✓ |

最後一行有個容易踩到的地方：標籤裡本來就有一個冒號。
ComfyUI 是**從最後一個冒號切**的，所以 `(artist:xxx:1.3)` 會被正確地讀成
「`artist:xxx` 這個標籤，權重 1.3」。這個我特地驗過。

### `artist:` 才是 NoobAI 的寫法（我原本寫錯了）

我之前一律用 `by xxx`，那是 Illustrious 的慣例。**NoobAI 官方 model card 的範例是：**

```
masterpiece, best quality, artist:john_kafka, artist:nixeu, artist:quasarcake, ...
```

所以現在改成看底模決定：

| 底模 | 寫法 | 出處 |
| --- | --- | --- |
| **NoobAI-XL** | `artist:amashiro_natsuki` | 官方 model card 的範例提詞 |
| **Illustrious** | `by amashiro_natsuki` | 官方／社群通行寫法 |
| Pony | （沒有用） | model card 說畫師名字被拿掉了 |

### 介面上怎麼用

角色包選好成員之後，「盡量貼近原畫師的畫風」下面多了一條**畫師權重**：

- 拉桿 0.6 ～ 1.6，旁邊有 **1.0 / 1.2 / 1.35** 三顆快捷鍵
- 右邊**即時顯示會實際送出去的那一段**，例如 `(artist:amashiro_natsuki:1.35)`
- 超過 1.45 會跳警告（顏色過飽和、線條糊）
- 底模換掉的時候，那一段會自動改成該底模的寫法

**如果你自己在提詞裡也打了一次同一個畫師**（`artist:yukisame` 或 `by yukisame`），
會被自動吸收掉 —— 兩個同一個畫師標籤用不同權重互拉，不是你按那個拉桿的意思。

常用範圍：**1.15 ～ 1.35**。加重就是提高畫風的比例，代價是角色本身的辨識度會被壓一點；
角色跑掉的話就往下調，或把角色的觸發詞也加重一點平衡回來。

## 14. 更新時出現「UPDATE DID NOT COMPLETE」，卡在 ComfyUI 那一段

### 先講你現在的狀態：app 其實已經更新好了

腳本的順序是這樣的，**ComfyUI 是最後一步**：

```
檢查 → 下載程式碼 → 解壓 → 確認可寫 → 複製程式碼 → 驗證大小 → 補裝套件 → 更新 ComfyUI → 完成
                                        ↑ 你已經走完這裡      ↑ 死在這裡
```

所以：

- **app 的程式碼是完整的、而且驗證過大小了**（不然它會停在更早的步驟）
- Python 套件也裝好了
- `git pull` **實際上跑完了**（那行 `From https://github.com/...` 就是 git 抓到東西之後才會印的）
- 唯一沒做到的是 ComfyUI 的 `requirements.txt` 補裝，以及最後那句 `UPDATE OK`

**你可以直接用。** 想確認 ComfyUI 更新到哪了，到「設定」分頁看，或按一次「立刻更新 ComfyUI」。

### 為什麼會這樣：git 把好消息寫在 stderr

`git pull` 成功的時候，會把 `From https://github.com/...` 印到 **stderr**，不是 stdout。
這不是錯誤，只是 git 的習慣。

而我那一行寫成 `2>&1 | Out-Null`，把 stderr 併進了管線。
**Windows PowerShell 5.1** 在 `$ErrorActionPreference = 'Stop'` 之下，
會把被重導的原生指令 stderr 變成一個**終止性錯誤**（`NativeCommandError`）——
於是一個已經成功的 pull 殺掉了整個腳本。

這是我的錯，而且錯得很典型：**拿 stderr 當成敗的判斷依據**。唯一誠實的訊號是結束代碼。

### 改了三件事

1. **`Invoke-Git` 包裝函式** —— 呼叫期間把 `$ErrorActionPreference` 設成 `Continue`，
   把輸出轉成字串，**只看結束代碼**。git 的訊息還是留著，失敗時會原文印給你看。
2. **整個 ComfyUI 區塊包在 `try/catch` 裡。** 這是更重要的一層：
   走到那裡的時候 app 的程式碼已經複製並驗證完了，
   **這個收尾步驟沒有資格讓整個更新失敗**。現在它最多降級成一行警告。
3. **新增一個 PowerShell 語法檢查**，三支 `.ps1` 都要能通過 parser。
   這些腳本沒辦法在 Linux 上完整執行，語法錯誤以前會直接送到你手上才爆。

### 老實說一句：這個 bug 我沒能在這裡重現

我裝了 PowerShell 7.6.4 實測，**舊的那一行在 PS7 底下不會死** ——
微軟在 7.x 改掉了這個行為。這個 bug 只在 **Windows PowerShell 5.1** 出現，
而 `update.bat` 用的正是 5.1（`powershell` 而不是 `pwsh`）。我沒辦法在 Linux 上跑 5.1。

所以我能驗的和不能驗的分開講：

| 驗過了 | 沒驗過 |
| --- | --- |
| 新的 `Invoke-Git` 面對「stderr 有輸出 + exit 0」回報成功，腳本活著 | 5.1 那個 `NativeCommandError` 本身 |
| 面對「stderr 有輸出 + exit 1」回報失敗，並把 git 的原因帶出來 | |
| 沒有任何原生呼叫在包裝函式外面併 stderr（這條就是當初該擋住那一行的檢查） | |
| 三支腳本都通過 PowerShell parser | |

下次跑 `update.bat`，最後一行應該是 `UPDATE OK`。要是又不是，把訊息貼給我。
