## 1. 系統在做什麼

一句話：**把三個立場不同的分析框架，接到同一份即時數據上，產出一份可查證、標明來源與過期狀態的美股狀態報告。**

## 2. 方法論來源

### 2.1 狠人的三層框架（本系統的骨架）

> **基本面管方向、流動性管顛簸、擁擠管斷裂——一個失控拖垮全部。**

| 層 | 管什麼 | 時間尺度 | 壞掉的樣子 |
| --- | --- | --- | --- |
| 基本面 | 方向 | 季度現金流累積，最慢 | 需求、獲利真的翻轉；慢，但會重估一切 |
| 流動性 | 顛簸（路徑） | 天到週 | 融資收緊、做市商退場；價格無消息跳空 |
| 擁擠 | 斷裂（時點） | 小時到天 | 同向部位同時強平；價格不是走出來是跳出來 |

核心主張：**極端行情幾乎從來不是三層一起壞掉，而是其中一層單獨失控把另外兩層拖下水。** 三個歷史案例分別對應三層失控：2022 英國 LDI 國債（流動性）、2021–23 Meta（基本面）、2021 GameStop（擁擠）。

**二波打法五步三開關**（逐字稿支撐，見 `playbook.md`）：

- 五步：定位籌碼結構 → 最上游找金絲雀（訂單/預付款/take-or-pay）→ 決策變數從利潤絕對值換成**增速的導數** → 看燃料（準備金）→ 看時間（8–12 週窗口）
- 三開關：① 燃料＝準備金 >2.8兆綠燈、無危機跌破 2.5兆無條件清倉 ② 點火＝選擇權偏度極端倒掛＋現貨抗跌 ③ **逃生＝雲廠商 capex 環比增速見頂回落 → 立刻平倉**
- 思科悖論：思科 2000 年營收 190 億、2001 年**逆勢升到 220 億**，股價同期 −88%。重資產資本開支有合約與工程剛性，所以 capex 在上漲時領先、下跌時嚴重落後。**盯絕對值＝盯後視鏡開車。**

### 2.2 Serenity 方法

瓶頸候選必須**四個條件同時成立**：(a) 客戶非有不可 (b) 供給無法快速增加 (c) 該公司已認證/設計導入 (d) **相對於機會而言便宜**。缺一項就降級。Buffett 品質閘門五個欄位**全部預設 `unverified`**，只有引用財報/法說/申報文件才能升級——單一則貼文不算證據。

### 2.3 equity-research

Anthropic 官方的賣方工作流：earnings-analysis、earnings-preview、catalyst-calendar、thesis-tracker、sector-overview、morning-note、initiating-coverage、model-update、idea-generation。

## 4. 我認為的問題

按「會不會讓結論失效」排序，不是按修起來難不難。

### 4.1 🔴 P0 — claim-check 有選擇偏差，而我在文件裡把它寫成了背書

**這是我認為最嚴重的一個，也是我自己犯的。**

`claim-checks.md` 目前的結論句是：「每一項可查證的宣稱都成立，好幾項精準到小數點。」數字本身沒錯——納指 −9.78%、美光 7/30 +18.36%、7/29 見底、準備金 2.993兆，全部對得上。

**問題在於樣本從哪來。** 這些宣稱**全部出自他的一支「對賬／復盤」影片**。復盤影片按定義就是作者挑選出來的成功案例。我等於是拿一個人自選的高光片段去給他打分，然後宣布他準確率極高——**這在統計上毫無意義**，而且我把它寫進 SKILL.md 當成「所以這個框架值得用」的理由。

更糟的是，這個評分結果現在是使用者信任整套系統的主要依據之一。

**這個偏差有多大，我不知道**，因為我沒有他失敗預測的樣本。合理推測：任何公開評論者的**未經篩選**命中率都會顯著低於自選樣本。

**提案**
- 立刻在 `claim-checks.md` 頂端加**選擇偏差警語**，並把結論句從「他很準」改成「**在他自選的樣本裡他很準，這不能推論到下一次**」。
- 建立 `references/forward-log.md`：從今天起，只記錄**事前**、有時間戳、有明確證偽條件的宣稱，事後回來評分。這才是有效樣本。
- 現有的回溯評分保留，但**降級**為「機制合理性佐證」，不再作為準確率證據。
- SKILL.md 裡「值得用作透鏡」的理由改成基於**框架的內在邏輯**（三層可分離、可獨立量測），而不是基於命中率。

### 4.2 🔴 P0 — 複合評分是我發明的，而且不可證偽

儀表板最上方的「**泡沫水位＝高**」和「**油量＝滿的**」，以及那兩條 12 格的刻度（我填了 9/12 和 8/12），**不是來源框架裡的東西，是我自己的判斷**，而且：

- 沒有公式。9/12 是怎麼來的？我憑感覺挑的。
- 沒有權重。我在文件裡主張「信用債是最誠實的指標」，但計分時它和 RRP 緩衝一樣算一票。
- **紅燈裡有兩個是過期資料**（0DTE 64% 是 41 天前、前十大權重 39.3% 是 41 天前）。也就是說「泡沫水位＝高」這個頭條結論，有一半建立在兩個月前的數字上。

這是整份儀表板最醒目的兩個數字，卻是最沒有根據的兩個。

**提案（三選一，我傾向 B）**
- **A**：寫出明確公式（各指標權重、正規化方式），公開在文件裡，接受批評。
- **B**：**刪掉複合分數**，改成直接呈現「幾綠幾黃幾紅（僅計即時指標）」＋一句話文字結論。少了視覺衝擊，但誠實。
- **C**：保留但明確標示為「作者主觀綜合判斷，非計算結果」，並且**排除過期指標**。

無論選哪個，**過期指標不得進入頭條計分**是硬性要求。

### 4.3 🔴 P0 — 逐字稿沒有存進 repo，distillation 無法稽核

`playbook.md` 是我從逐字稿萃取的。但**逐字稿本身沒有存進 repo**。這代表：

- 如果我萃取錯了、漏了、或加油添醋，**沒有任何方法可以查**。
- 而我已經在 Meta 那一條上犯過一次「讀標題不讀來源」的錯，方向還是反的。

這直接違反系統自己宣稱的原則（「每個數字都要能追回來源」）。

**提案**：建立 `references/transcripts/<videoId>.txt`，存原始逐字稿，`corpus.md` 每一條註明對應行號區間。若有版權疑慮，至少存**帶時間戳的關鍵段落引用**。

### 4.4 🟠 P1 — 最重要的那個開關，是唯一沒接上的

**開關三（雲廠商 capex 環比增速）是他整套打法裡唯一的逃生鈴**，也是唯一能翻轉「基本面管方向」那一層的東西。他自己的規則是：這個一響，不管當期獲利多漂亮，**立刻平倉**。

目前它的值是 `null`。沒有腳本、沒有資料、沒有歷史序列。

也就是說：**整套系統最重要的訊號，現在是關掉的**，而儀表板上它顯示為黃燈（🟡），視覺上跟「輕微注意」沒有區別。使用者很容易以為它在運作。

**提案**
- 建 `references/hyperscaler-capex.json`：MSFT / GOOGL / AMZN / META 逐季 capex，手動維護但有明確 schema 和 QoQ 計算。
- 補歷史序列（至少 8 季），這樣才看得出「增速是否見頂」而不只是單點。
- 儀表板上把「未接線」和「黃燈」在視覺上分開——建議用灰色斜線底紋 + 明確標籤「未接線」。
- 中期：從 SEC EDGAR 的 10-Q XBRL 自動抓 `PaymentsToAcquirePropertyPlantAndEquipment`。

### 4.5 🟠 P1 — 儀表板的數字是手抄的

`reports/us-market-dashboard.html` 裡的 `GAUGES` 陣列是我**手動從腳本輸出抄進去的**。所以：

- 重跑腳本不會更新儀表板。
- 抄錯不會有任何警告。
- 「按一下就重跑」這個承諾目前**只有一半是真的**——腳本會重跑，儀表板要重抄。

**提案**：寫 `scripts/render-dashboard.mjs`，讀 `gauges.json` + `snapshot.json` 產生 HTML；HTML 改成模板。並加一個 CI 檢查：HTML 裡的數字必須與 JSON 一致，否則 fail。

### 4.6 🟠 P1 — Serenity 和 equity-research 兩個鏡頭實際上是裝飾

系統宣稱有三個鏡頭。實際上：

- **Serenity 的 Buffett 閘門五個欄位全部停在 `unverified`**，因為系統**沒有任何抓財報的能力**。它永遠不可能升級。等於這個鏡頭只提供了一個「保持懷疑」的態度，沒有提供分析。
- **equity-research 完全沒有被執行過**。我 vendored 進來、在 README 裡描述、在對話裡引用它的存在，但 brief 和 dashboard 的產生過程中**它一次都沒有被實際使用**。

這是誇大了系統能力。使用者以為有三個獨立驗證，實際上只有一個（狠人的價格/流動性層）在運作。

**提案**
- 加 `scripts/fundamentals.mjs`：抓營收、毛利率、FCF、capex（Yahoo `quoteSummary` 或 SEC EDGAR companyfacts API，後者免費且權威）。
- 有了財報數字，Buffett 閘門才能真的升級/降級。
- equity-research：至少讓 `earnings-analysis` 和 `catalyst-calendar` 實際跑在持股上，或者**從 README 的宣稱裡拿掉**，不要留著當門面。

### 4.7 🟡 P2 — 沒有歷史，看不到趨勢

每次執行都是快照，不存檔。但這套框架的核心變數**恰恰是趨勢**：

- 準備金從 3.1兆 → 2.98兆 → 2.99兆，是在往 2.8兆 逼近還是在回填？單點看不出來。
- 他自己的規則寫的是「**快速**跌破 2.5兆」——「快速」是斜率，快照根本量不出來。
- 系統也因此**無法被自己的標準檢驗**：沒有歷史判斷紀錄，就永遠不能算自己的準確率。（我們拿這個標準去評狠人，卻不套在自己身上。）

**提案**：每次執行 append 一行到 `data/gauge-history.jsonl`；儀表板每個指標加 90 天走勢縮圖；`predictions.md` 記錄每次的結論與證偽條件，日後回評。

### 4.8 🟡 P2 — 日期錯配讓兩個指標算出來的東西不是它宣稱的東西

- **M2 增負差**：M2 最新只到 **2026-06-01**，卻拿去和 **2026-08-07** 的納指比。這不是「同期年增差」，是拿兩個月前的貨幣數據對今天的股價。目前讀數 −22（黃燈），距離紅燈門檻 −25 只差 3——這個誤差量級足以改變燈號。
- **巴菲特指標**：分子（企業股權）停在 **2026-01-01**，分母（GDP）是 **2026-04-01**，兩者差一季，而且都落後現在 4–7 個月。目前 214%（紅燈），但這個 214% 描述的是**七個月前**的市場。

**提案**：兩者都改成「**對齊到同一日期**」計算，並在儀表板上顯示**資料落後天數**而不只是 as-of 日期。落後超過 60 天的指標，燈號應自動降級為「參考」。

### 4.9 🟡 P2 — 門檻值全部沒有回測

2.8兆 / 2.5兆 / 3bp / 5× / 60% 0DTE / 35% 前十大權重——**這些數字全部來自「他講的」**，沒有一個做過歷史檢驗。我們不知道：

- 這些門檻的**假警報率**是多少？
- 準備金跌破 2.8兆 在歷史上發生過幾次？後續三個月報酬分布如何？
- 「個股波動 5× 大盤」在過去十年觸發過幾次？之後真的斷裂了幾次？

一個沒有假警報率的訊號，使用者無法判斷該多認真看待它。

**提案**：寫 `scripts/backtest-thresholds.mjs`，對每個有長歷史的 FRED/Yahoo 指標跑：觸發次數、觸發後 1/3/6 個月的報酬分布、假警報率。結果寫進 `references/threshold-validation.md`。**做不到的就明講「未驗證」**。

### 4.10 🟡 P2 — 單一資料源、無快取、無可重現性

- Yahoo 的 chart endpoint 是**非官方**的，隨時可能改或封。沒有 fallback。
- 沒有快取。同一天跑兩次可能拿到不同數字（盤中更新），而且**沒有任何紀錄說明當時拿到的是什麼**。報告因此不可重現。
- FRED 也是單點依賴（雖然穩定得多）。

**提案**：每次抓取存 raw response 到 `data/raw/YYYY-MM-DD/`；加 Stooq 或 Alpha Vantage 作為價格 fallback；報告內嵌資料指紋（hash）。

### 4.11 🟢 P3 — 開關二是代理指標，可能和真訊號不一致

他的原始訊號是**選擇權 put/call 偏度極端倒掛 + 現貨抗跌**。我用的是 **VIX 期限結構**（`^VIX`/`^VIX3M`）。

兩者相關但不等價：偏度講的是**尾部定價的不對稱**，期限結構講的是**恐慌的時間分布**。可以出現期限結構已回到 contango（我的代理報綠燈）但偏度仍極端（他的訊號還沒觸發）的情況，反之亦然。

目前儀表板有標「（代理指標）」，但沒有說明**它可能給出相反答案**。

**提案**：文字說明加上「此代理與原訊號可能不一致」；若能取得 CBOE SKEW 指數（有免費日資料）則改用或並列。

### 4.12 🟢 P3 — 持股是寫死的，也沒有風險框架

- `SNDK` / `MU` 是硬編碼在 `gauges.mjs` 的擁擠度清單和儀表板 HTML 裡。應該是 `config/portfolio.json`。
- 系統**完全不知道部位大小、成本、佔資產比重**，所以任何關於「該不該出清」的討論都缺少最關鍵的變數。
- 諷刺的是，系統引用了他的**賭徒破產定理**（方向錯了，本金再大也歸零），卻沒有任何地方處理使用者的實際風險暴露。

**提案**：加 `config/portfolio.json`（ticker、股數、成本、佔比可選）；儀表板加一區「你的部位在這個框架裡的暴露」。**但明確不做部位建議**——只呈現暴露事實（例如：「你的兩檔持股相關係數 0.9x，同日見高、同日見底，等於單一因子」）。

### 4.13 🟢 P3 — 護欄是散文，不是程式

「不出買賣訊號」目前只寫在 SKILL.md 的散文裡。沒有任何機制阻止未來某次執行輸出「建議買進」。這在一個處理真實持股的系統裡，是個結構性弱點。

**提案**：加 `references/guardrails.md` 明列禁止輸出的句式；報告產生後跑一個 lint 檢查關鍵詞（目標價、建議買進/賣出、應該加碼）。

## 6. 我沒有把握的地方，想聽第二意見

1. **回溯評分該不該整個作廢？** 我傾向保留但降級。反方論點是：一個有選擇偏差的評分放在文件裡，不管加多少警語，讀者還是會被「6/6 命中」的表格影響。也許該直接刪掉。

2. **手動指標到底該不該顯示？** 目前顯示但標灰。另一種做法是**過期就隱藏**。顯示的好處是完整性，壞處是它們仍然在視覺上參與了「泡沫水位＝高」的印象。

3. **這套系統是否根本不該處理使用者的個股？** 目前它會呈現持股的擁擠度和位置，但不給建議。這條線畫得對嗎？還是只要碰到具體持股，就已經滑向投資建議了？

4. **三個鏡頭的獨立性有多真？** Serenity 和 equity-research 都是基本面導向。真正獨立的其實只有「狠人的部位/流動性視角」對上「基本面視角」——所以與其說三個鏡頭，也許誠實的說法是**兩個**。

5. **有沒有更根本的問題**：這套框架建立在一個 YouTube 評論者的公開影片上。即使他的邏輯自洽、數字精準，把他當成系統骨架是否本身就是個錯誤的架構決策？有沒有更好的做法（例如直接用學術文獻的流動性/擁擠度指標，把他的框架降為其中一個參照）？
