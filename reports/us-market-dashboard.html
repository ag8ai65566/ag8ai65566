What the tests actually test

測試分類 · 「59/59 通過」本身不是保證

一個總數聽起來像保證，但它沒說通過的是哪一個問題。 這裡把測試依照它們回答的問題分開 —— 最後一格是空的，而那格才是重點。

15/15
時間對齊

兩條序列是不是在同一個時間點上被比較？

這一層的每個測試都對應一個真的出過的錯 —— 六月的 M2 對上八月的那斯達克，把一個紅燈壓成黃燈。

27/27
計算一致性

畫面上的數字，是不是引擎算出來的那一個？

renderer 不准做任何金融運算，連 /1e9 和四捨五入都不行。這一層負責讓這條規則不只是註解。

7/7
輸出契約

這份輸出有沒有可能夾帶買賣建議、目標價或綜合評分？

在結構化資料上檢查，不是掃 HTML —— 舊做法連續三次抓到自己的免責聲明。

Canonical data flow　FRED / SEC EDGAR / Yahoo → data/raw/ → gauges.mjs (calc v4.0.0) → data/gauges.json → render-dashboard.mjs → 本頁。 這個 renderer 不做任何金融計算 —— 沒有 YoY、沒有百分位、沒有中位數、沒有利差、沒有訊號邏輯。 頁面上每個數字都是引擎算好的欄位。

FRED 的預設端點只回傳最新修訂版，所以目前的讀數描述現在、不是可回測的歷史。但這是「尚未實作」，不是「結構上不可能」—— ALFRED 提供 vintage 資料，FRED API 也有 series/vintagedates，回測路徑並沒有被資料架構永久封死。SEC 那條已帶 filed 時間戳，as-of 查詢也已實際執行並通過測試（站在 2026-07-15 看不到 2026-08-06 才申報的那一季），所以 point-in-time 目前是 FRED 這一側缺 vintage，不是整條路徑都缺。
