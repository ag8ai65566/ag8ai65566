## 3. 本週的不對稱 —— 這份 brief 的重點

### 3.1 「AI 行情回來了」這句話對指數成立，對你手上的東西不成立

媒體本週的說法是 AI 交易回歸、標普創高。指數層面屬實。
但把 AI 這個籃子拆開，它已經分成兩半：

| 近一個月 | | 距兩年高點 | |
| --- | --- | --- | --- |
| MSFT | **+27.9%** | NVDA | −4.9% |
| PLTR | **+27.9%** | AMZN | −5.9% |
| AMZN | +8.0% | MSFT | −9.2% |
| NVDA | +5.8% | TSM | −10.1% |
| — | — | AVGO | −13.6% |
| GOOGL | **−11.3%** | GOOGL | −14.7% |
| AMD | **−11.9%** | AMD | −16.9% |
| META | **−12.4%** | **MU** | **−24.9%** |
| **SNDK** | **−23.5%** | **META** | **−26.3%** |
| **MU** | **−7.3%** | **SNDK** | **−42.4%** |

這是**分層塌方**的形狀：指數在睡覺（21 日波動 13.7%），而籃子裡有五檔用
年化三位數的波動在跑。狠人的框架裡，這一層管的是斷裂——而斷裂已經在發生，
只是還沒傳導到指數。

### 3.2 逃生鈴響了嗎？沒有，而且是加速的相反方向

四家雲廠商 2026-Q2 capex 合計 **$165.05B**（2026-03-31 季為 $129.75B）：

| | 2026-Q2 | 差分還原 |
| --- | --- | --- |
| AMZN | $54.21B | 否（直接申報） |
| GOOGL | $44.92B | 是 |
| MSFT | $35.80B | 是 |
| META | $30.12B | 是 |

**環比 +27.21%、年增 +87.03%，兩者都是整個序列的最高點。**
他的規則是「環比增速見頂回落就立刻平倉」——目前不但沒回落，還在加速。
按他的原話，**逃生鈴沒有響**。

### 3.3 這裡有一個他的規則沒有涵蓋的東西（我的觀察，不是他的話）

他的邏輯是：capex 增速是需求的代理，增速回落＝需求見頂＝出場。
但本季市場的反應是相反的——Alphabet 上調 2026 資本支出後股價下跌約 7%，
Amazon、Meta、Microsoft 同步走弱。

也就是說，**市場已經開始把 capex 上升讀成「成本與投資報酬率的問題」，
而不是「需求強勁的證據」。** 如果這個轉變持續，那麼「等環比見頂回落再出場」
會是一個**永遠遲到**的訊號：價格會先反映 ROI 疑慮，資料再過一季才確認增速轉折。

這不是說他錯了，而是說**這條規則的前提（capex↑＝好消息）在本季不成立**。
這一點目前沒有任何驗證，屬於觀察，不是判定。

### 3.4 你的兩檔是同一筆交易

MU 與 SNDK 日報酬相關係數 **0.766**（259 個交易日）。
標籤上一個是 DRAM/HBM、一個是 NAND，但價格說它們是同一個因子。
兩檔合計不是一個組合，是一個部位的兩種寫法。

## 7. 一個系統層面的發現：08-11 那個標籤下錯了

兩天前這一格顯示 `INGESTION_OVERDUE`，並寫著「MSFT、GOOGL、AMZN 已申報到 2026-Q2，
但 META 在本管線讀取的路徑上尚無該季資料——這是取得路徑的限制，不是來源沒有公布」。

今天回頭比對兩次執行的原始 SEC 回應：

```
2026-08-11 的 META companyconcept 回應：只到 2026-03-31
2026-08-13 的 META companyconcept 回應：多了 2026-01-01 → 2026-06-30，filed 2026-07-30
```

META 的 10-Q **在 2026-07-30 就申報了**，但 SEC 的 `companyconcept` API 在 08-11 還沒有
把那筆 fact 索引進去。所以真正的原因既不是「管線沒去拿」，也不是「來源沒公布」，
而是**第三種**：來源已收件，但這個 API 端面尚未索引。

`INGESTION_OVERDUE` 這個標籤把責任指向了我的管線，而實際上管線抓了、也抓對了。
三層新鮮度模型少了一層：`latest_available` 目前是**用同一個 API 推出來的**，
所以它結構上無法分辨「發行人已申報」和「這個端面已索引」。

**修法**：改用 EDGAR submissions feed（申報一進系統就列出 accession）當作
「發行人是否已申報」的獨立來源，與 companyconcept 是否已有該筆 fact 分開判斷。
這個修改還沒做——它不影響今天的讀數，但它是一個標籤誠實度的問題，已列入下一輪。
